## 테스트 3개 / Three tests (대상 / 검증 내용)

1. **`test/engine.test.js`** / 실전 재현 엔진의 마감 계산 (`closeSec`, `seatsLeft`): 같은 입력이면 같은 결과가 나오고, 희망/제한 비율이 높은 과목이 먼저 마감된다. 희망 × 신청 비율이 제한 이하인 과목은 마감되지 않고, 남은 자리는 마감 시각에 정확히 0이 된다. 목업 과목, 경계값(희망 0, 제한 0·1 등), 넓은 격자를 MODEL 값 5가지로 돌린다. (#1, D1)
2. **`test/summary.test.js`** / 신청 판정과 결과 요약 (`judge`, `summarize`): 시작 전은 기간 아님, 마감 전에 누르면 성공, 마감 시각부터는 정원 초과. 요약에는 안 누른 과목까지 모든 과목이 나오고, 화면 메시지와 요약이 같은 판정을 쓴다. (#4, D4)
3. **`test/queue.test.js`** / 대기열 (`queueAt`): 기다릴수록 앞 인원이 줄고 진행률이 올라 예상 시간이 지나면 통과한다. [닫기] 후 다시 서면 그대로 기다렸을 때보다 앞서지 않고, 몰리는 동안 다시 서면 순번이 뒤로 밀린다. (#5, D5)
- 별도로 PR마다 자동 검사 `scripts/check.js`가 돈다. JS 문법, `manifest.json`, `files.js` 목록, 원칙(외부 요청 함수 금지, `chrome.*`은 `background.js`에서만)을 확인한다.
- 현재 결과: 테스트 14개 모두 통과, 자동 검사 통과 (JS 8개)

## AI 코드리뷰 관점 2개 / 주요 지적 / Two review perspectives

**관점 1: 안전·원칙** (학교 서버로 요청 안 보냄, 실제 신청 차단, 개인정보)

- 원칙 검사(`check.js`)가 글자 검사라서 이미지·링크 주소로 나가는 요청을 잡지 못한다. 위 실험에서 실제로 통과했다.
- 실제 신청을 막는 클릭 차단(`core.js`의 `guard`)이 이 확장에서 가장 중요한 안전장치인데, 이를 확인하는 자동 테스트가 없다.
- 확장만 켠 상태에서 허용하는 조작(조회, 페이지 이동, 메뉴)은 학교 화면이 스스로 조회 요청을 보낸다. “학교 제한을 건드리지 않는다”는 원칙과 맞는지 문서로 정리돼 있지 않다 (#19에서 확인 필요로 남김).
- 개인정보: 확장은 화면 제목과 표만 읽고 저장·전송하지 않는다. 팀원 계정 화면 저장본(`화면/`)과 확장 서명 키(`.pem`)는 `.gitignore`로 빠져 있다. → 문제 없음

**관점 2: 테스트·정확성**

- CI(`check.yml`)는 `node scripts/check.js`만 돌리고 `node --test`는 돌리지 않는다. 판정 스크립트가 PR에서 자동으로 실행되지 않는다.
- 같은 과목을 여러 번 누르는 경우를 테스트하지 않아서, 판정을 마지막 클릭으로 바꾸는 버그를 놓친다.
- 테스트가 화면과 분리된 `engine.js`만 다룬다. 팁 찾기(`matchTip`), 모드 시작 실패 처리, 클릭 허용 목록(`idleAllow`)은 사람이 목업에서 눌러 보는 것으로만 확인한다.
- 모달이 떠 있을 때 Tab으로 포커스가 모달 밖으로 나가 가짜 [신청]이 눌린다 (#15).

## 받아들이지 않은 지적과 이유 / Findings rejected and why

| 지적 | 받아들이지 않은 이유 |
| --- | --- |
| 원칙 검사를 정규식 대신 AST 분석(ESLint 등)으로 바꿔라 | “설치할 것 없는 빌드 없는 JS” 원칙과 맞지 않는다. 확장 코드는 팀원만 쓰고 모든 PR을 사람이 리뷰하므로, 일부러 우회할 가능성은 리뷰로 막는다. 대신 `new Image`, `src=`, `location` 같은 패턴을 검사 목록에 더하는 것은 검토한다 |
| 확장만 켠 상태에서도 조회·페이지 이동·메뉴 클릭을 모두 막아라 | 사용자가 직접 누르는 것과 같은 조회(읽기)이고, 막으면 화면을 옮길 수 없어 연습이 안 된다. 원칙은 “확장이 요청을 만들지 않는다”와 “신청·삭제 같은 서버 상태 변경을 막는다”이다 |
| 클릭 차단(`guard`)을 브라우저 자동화(Playwright 등)로 테스트하라 | 설치가 필요하고 발표(12/2)까지 시간이 없다. 대신 N7 실제 화면 적용 테스트에서 체크리스트로 직접 확인한다 |

## 배포 전 점검 / Pre-deployment check

- [x]  키 노출 없음 No keys: API 키·외부 서버가 없다. 확장 서명 키 `.pem`, `.crx`, `.zip`은 `.gitignore`에 들어 있다
- [x]  입력 검증 Input validation: 확장은 페이지 글자를 `textContent`로만 넣는다 (innerHTML 금지). 목업은 입력값을 수업번호 조회 키로만 쓰고, 대화상자에 넣는 값은 `escapeAttr`로 처리한다
- [x]  오류 노출 없음 No error leakage: 모드 시작 실패 시 사용자에게는 안내 문구만 보여 주고(예: “희망수업에 신청할 과목이 없어요”), 상세 내용은 콘솔에만 남긴다
- [ ]  외부 장애 대응 External failure: 화면을 못 찾으면 5초 뒤 “시간 초과”로 모드가 꺼지고 페이지를 다시 누를 수 있다 (#19). 학교가 화면 구조를 바꾸면 선택자가 깨지는데, 이를 알려 줄 방법은 아직 없다. 목 사이트 기본 주소 `/`는 404다 (#25)

## 알고도 고치지 못한 것 / Known and unfixed → `ETHICS.md` 5절

| 문제 | 왜 못 고쳤나 | 사용자에게 알릴 것인가 |
| --- | --- | --- |
| 마감 속도·대기열 값(`MODEL`, `QUEUE`)은 근거 없는 임시값이다 | 과목별 실제 마감 시각과 대기 시간 자료가 없다 | 예. “실제 경쟁률이 아닌 희망·제한 인원 기반 추정치”라고 안내한다 |
| 대기 화면의 모양과 문구가 실제와 다를 수 있다 | 실제 대기열 화면 템플릿을 보지 못했다 | 예 |
| 학교가 화면 구조를 바꾸면 팁·차단이 동작하지 않을 수 있다 | 실제 화면 테스트는 수강신청 기간이 아닐 때만 할 수 있다 | 예. PC 크롬 전용, 화면 변경 시 동작 안 할 수 있음을 안내한다 |
| 사회봉사·국제여름/겨울학교 메뉴는 팁이 없고, 확장을 켜면 열리지 않는다 (#18) | MVP 범위에서 제외했다 | 예 |
| 모달이 떠 있을 때 Tab으로 포커스가 밖으로 나간다 (#15) | 공용 모달을 `<dialog>`로 바꾸는 범위가 크다 | 아니오 (마우스 사용 시 영향 없음). 고칠 때까지 이슈로 둔다 |
| 원칙 검사가 이미지·링크로 나가는 요청을 잡지 못한다 | 글자 검사의 한계 | 아니오 (내부 개발 검사). 코드 리뷰로 보완한다 |
