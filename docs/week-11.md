## 데모 시나리오 / Demo scenario — 사용자 한 명의 이야기

> 26학번 신입생 A는 2/27에 첫 수강신청을 한다. 모의수강신청(2/2~2/4)은 2학년 이상만 대상이라 연습할 기회가 없었고, 수강신청 화면은 처음 본다.
> 
1. A가 목 사이트(https://freshman-simulator.vercel.app/mock/index.html, 가상 데이터)를 열고 확장을 켠다.
2. **자유 팁 모드 (기능 3)**: 팁이 있는 요소에 마우스를 올리면 얇은 테두리와 “?” 배지가 뜬다. “희망인원 176인데 잔여석 9?”가 궁금해서 인원 칸을 누르자 설명 말풍선이 뜬다. 팁이 없는 요소는 눌러도 반응이 없다. (#2, #16 / PR #14, #22)
3. **실전 재현 (기능 2)**: 희망수업 화면에서 실전 재현을 시작한다. 5초 카운트다운 후 1순위 과목의 [신청]을 누르자 대기열 화면이 뜬다. 급해서 [닫기]를 누르고 다시 신청하자 순번이 뒤로 밀린다. (#1, #5 / PR #7, #20)
4. 대기가 끝나자 1순위 과목은 “정원이 초과되었습니다”가 뜬다. A는 플랜B 과목을 바로 신청해 성공한다. (#4 / PR #10)
5. [연습 끝내기]를 누르면 결과 요약에 과목별 성공·정원 초과, 누른 시각과 마감 시각의 차이가 나온다.
6. 확장이 켜진 동안 실제 신청 버튼은 막혀 있어 목업의 신청 내역이 바뀌지 않고, 학교 서버로 가는 요청도 없다.
- 신입생 튜토리얼(기능 1, #3)이 머지되면 1과 2 사이에 넣는다: 수강편람으로 이동해 기본수업·희망수업·수강신청 화면의 요소를 차례로 눌러 보며 따라간다.

## 시연 결과 / 실패 지점 / Result and failure point

**동작한 것 (목업 기준)**: 자유 팁(팁 데이터 + 테두리·반응 없음), 실전 재현 엔진, 가짜 신청 버튼·결과 모달, 대기열 팝업, 실제 신청 버튼 차단

**실패·미완 지점**

1. **신입생 튜토리얼 미반영 (D3, #3)**: 11/15 기준 “UI 완료, 문구 다듬는 중”이지만 GitHub에 브랜치·PR이 없다. `tutorial.js`는 10/7 뼈대 그대로라 데모 시나리오의 첫 단계를 보여 주지 못한다. MVP 마일스톤(D0~D4) 중 남은 것은 이것 하나다. 11/18까지 PR을 올리기로 했다.
2. **실제 화면 미검증 (N7)**: 목업이 실제 화면과 달라서, 실제 화면에서 팁 7개를 찾지 못하는 문제(#18)와 disabled 칸·라디오·페이지 이동이 막히는 문제(#19)가 늦게 드러났다. 11/18에 PR #23, #24로 고쳐 머지했지만 실제 사이트 확인은 11/20(N7)에 한다.
3. **모달 포커스 (#15, 미해결)**: 모달이 떠 있을 때 Tab으로 포커스가 밖으로 나가, 시작 안내 모달 위에서 Tab → [신청] → Enter를 누르면 메시지가 겹쳐 뜬다.
4. **배포 주소 (#25)**: 기본 주소 `/`가 404라 `/mock/index.html`로 직접 들어가야 한다.
